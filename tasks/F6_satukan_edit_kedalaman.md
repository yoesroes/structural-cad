# F6 — Satukan logika edit kedalaman dan panjang zona (server = otoritas)
Prasyarat: F4 selesai.
**Berkas boleh diubah:** `src/scad_ui/server.py`, `src/scad/` (fungsi pembantu baru `ops.py`), `web/src/commands/apply.ts`, `examples/ops_golden.json` (baru), tes Python dan TS.
**Latar:** `POST /api/pile/{id}/depth` selalu menulis override walau nilainya sama dengan default grup (tersisa `{"depth_below_cof": 30000}`), sedangkan `web/src/commands/apply.ts` menghapusnya. Logika sama di dua tempat dengan perilaku berbeda.
**Langkah:**
1. `src/scad/ops.py`: `apply_operation(doc, op) -> (doc_baru, inverse|None)` murni (tidak mengubah masukan), operasi sesuai `web/src/types.ts` (`set_pile_depth`, `reset_pile_depth`, `set_pile_zone_length`, `reset_pile_zone_length`). Aturan: nilai harus > 0; bila sama dengan nilai efektif grup (definisi -> `defaults.params`, atau panjang zona definisi) hapus override dan wadah kosong (`overrides.params`, `overrides.zone_lengths`, `overrides`); id zona/pile tak dikenal -> `ValueError` berpesan Indonesia.
2. Server memakai `ops.apply_operation`, memvalidasi (`validate_document`), menyimpan, dan membalas `{"ok": true, "pile": <ResolvedPile>}` (hasil resolve pile itu). Endpoint: `POST /api/pile/{id}/depth` {depth}, `POST /api/pile/{id}/zone` {zone, length}, `POST /api/pile/{id}/reset` {field: "depth" | "zone:<id>"}. Galat -> 400 dengan `issues`.
3. `examples/ops_golden.json`: daftar kasus `{doc_ref, op, expected_overrides, expected_inverse}` (minimal 10: set baru, set sama dengan default, set Z2=7000, reset, reset yang tidak ada, nilai 0, negatif, pile tak ada, zona tak ada, inverse bolak-balik). Tes Python dan tes TS keduanya membaca berkas ini; kedua implementasi harus menghasilkan hasil identik.
**Kriteria selesai:** semua kasus golden lolos di Python (pytest) dan TS (node:test); tes server: set 30000 pada P1-1 tidak meninggalkan `overrides`; P1-8 (`zone:Z2` = 7000) lalu reset menghapus `zone_lengths`; baseline tes tidak turun.
